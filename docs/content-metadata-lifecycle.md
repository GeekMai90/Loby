# 内容元数据与生命周期

## 目标

元数据帮助作者组织、筛选和发布内容，但不能让 Markdown 失去可读性，也不能把业务状态拆成多个互相冲突的事实来源。

## 三层模型

### 文稿属性定义

文稿属性由系统属性和作者新增的自定义属性组成。自定义属性包含稳定 ID、键名、显示名称、类型、说明、选项和默认值；它们按项目隔离，让同一项目中的文稿共享一套属性结构，但产品归属仍然是文稿。“目标字数”以锁定系统定义出现在项目的文稿属性管理器中，只开放创建默认值；标签、`description` 与时间等其他系统元信息不进入项目定义列表。

### 文稿属性值

每篇文稿直接拥有稳定 ID、标题、状态、标签、目标字数、`description`、`createdAt`/`updatedAt` 等系统元信息，并保存文稿自定义属性的实际值。系统字段由文稿模型解释，自定义值由当前项目作用域内的文稿属性定义解释；扫描现有 Loby 写作库时保留未知但合法的自定义值，外部 Markdown 导入则只接受系统字段和目标项目中已定义、类型兼容的自定义值。系统不另设 `date`；用户新增的“发布日期”仍是项目作用域内的普通自定义字段。

### 新建项目与文稿

用户新建项目只创建通用项目容器，不预设目标平台、业务标签、提纲、素材库或发布检查文稿；首次建库生成的“落笔指南”是独立的产品教程，不参与模板或普通项目默认值。新文稿由文稿模型直接补齐必要系统元信息：普通项目中的文稿继承该项目“文稿属性”的目标默认值，不在项目中创建的文稿继承写作设置映射到收件箱的目标默认值，再取得其他自定义属性默认值；创建完成后所有实际值都归文稿自身，来源默认值不再与它持续绑定。

## 字段类型

当前领域模型支持文本、长文本、数字、开关、日期、单选、多选和标签类值。新增类型必须同时定义：

- TypeScript 与 Rust 表示；
- UI 编辑、空值和只读行为；
- TOML/frontmatter 序列化；
- 搜索、筛选和发布转换；
- 旧值到新类型的迁移或拒绝策略。

## 所有权

### 系统元数据

稳定 ID、标题、状态、标签、`description`、目标字数、`createdAt`/`updatedAt`、归档/完成时间的实际值由文稿模型统一维护。项目只保存锁定的“目标字数”定义及其新文稿创建默认值，不得批量覆盖已有文稿；调用方也不得在多个组件里各自推导。

### 功能字段

项目 writing brief、目标、发布清单、导出记录和项目专属的帮助中心绑定属于项目模型，持久化在 `project.toml`。可跨项目复用的 GitHub 渠道目标仍属于应用级 registry。文稿属性与 GitHub 发布身份属于文稿，持久化在 Markdown frontmatter；GitHub Token 不属于内容元数据。

### 文稿自定义属性

用户可以在“文稿属性管理”中添加、修改和删除当前项目作用域内的文稿自定义属性。删除正在使用的属性或选项、改变不兼容类型时必须展示影响范围，并要求选择替换、清空或取消，不能静默丢失值。

## 界面

- 当前文稿元数据从编辑器工具栏的“信息”弹出面板编辑。
- 项目右键的“文稿属性” Dialog 固定展示“目标字数”系统项并允许设置该项目的新文稿默认值，同时维护当前项目的自定义属性定义。
- “设置 → 写作 → 通用”的“收件箱默认目标字数”编辑同一套收件箱属性定义，只影响以后在项目之外新建的文稿，不另建全局目标状态。
- 列表、搜索和筛选消费同一份标准化模型，不建立第二份仅供界面使用的数据。
- 空值是否显示由字段定义决定；界面不得把空字符串、`null` 和缺失字段混成不可预测状态。

## 持久化

### 项目

普通项目的 `project.toml` 保存项目身份与状态、writing brief、纯项目目标、按项目隔离的 `documentPropertyDefinitions`、分组、文稿元数据索引、发布清单、导出历史，以及可选的非敏感 `[helpCenter]` 绑定和 `[[helpCenterGroups]]` 映射；收件箱的同类模型保存在写作库索引中。其中 `targetWords` 定义只保存新文稿创建默认值，不是某篇文稿的目标，也不是项目总目标；项目不保存项目级文章描述或文章标签。可跨项目使用的 GitHub 发布目标保存在平台 app-config，项目专属帮助中心绑定只引用仓库，不拥有凭证。`[loby] project = true` 标记由 Loby 管理的完整项目文件。

### 文稿

Markdown frontmatter 保存应用拥有字段与自定义属性，正文保持普通 Markdown。公开通用字段使用顶层 `title`、`tags`、`description`、`createdAt` 与 `updatedAt`；Loby 私有身份和状态保留在 `loby` 命名空间，不再写入无独立语义的 `lobySheet` 标记。文稿身份统一使用 `sheet-` 加 26 位小写 Crockford Base32；外部导入始终生成新 ID，旧格式和缺失 ID 由用户主动重建索引统一迁移。保存流程集中渲染 frontmatter；外部导入按 `markdown-import.md` 的白名单和目标项目定义转换常见顶级字段，不继承另一个应用或写作库的内部身份。

### 开发期迁移

- 当前仍处于单用户开发阶段，字段边界调整由加载时单向归一化和下一次保存完成升级；旧 `summary` 只作为迁移输入或外部导入别名，运行时与新文件统一使用 `description`。
- 扫描当前写作库时不认识的合法文稿自定义元数据默认保留；外部导入的陌生字段必须在预览中列为丢弃项。
- 一次性数据升级必须幂等；重复打开和保存不应继续改变文件。
- 元数据解析失败时保留原始正文并显示问题，不能静默覆盖。

## 发布

发布适配器从标准化文稿模型、应用级目标或当前项目帮助中心绑定读取渠道所需值。渠道映射和临时转换属于发布层，不把微信、墨问等专属字段写进编辑器核心模型；GitHub 首次发布后把稳定 source identity、slug、URL、commit SHA、来源 hash 和时间按目标 ID 写入 `loby.publications.<targetId>`，帮助中心固定使用 `help-center` 记录键。source identity 用于重建索引迁移后继续匹配远端清单或 `.publish.json`，不得因内部文稿 ID 升级而改写；不同目标的发布记录互相隔离。发布凭证永远不属于内容元数据。

## 归档与废纸篓

- 归档是可逆状态变化，内容仍留在原结构中并可搜索或恢复。
- 废纸篓是文件级移动：项目、文稿和图片进入 `.loby/trash/`，同时保存恢复所需 manifest。
- “清理空白文稿”只识别正文为空且标题为空或为“无标题”的文稿，并逐篇移动到废纸篓；普通保存不执行递归清扫，也不根据内存模型缺失硬删除 Markdown。
- 恢复必须处理原路径被占用、父项目缺失和文件已变化等情况。
- 永久清空属于显式破坏性操作，目标和影响数量必须清楚可见。

## 验收条件

- 应用重启、外部刷新和导入导出后字段值不丢失。
- 改字段类型、删选项、移动文稿、归档与恢复都有确定结果。
- Markdown 离开 Loby 后仍可读，未知元数据不会被无声删除。
- TypeScript 模型、Rust 模型、序列化与界面使用同一套语义。
