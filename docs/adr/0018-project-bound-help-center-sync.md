# ADR 0018：项目绑定的帮助中心同步

## 状态

Accepted — 2026-07-30

## 背景

落笔需要把一个本地写作项目投影为 Astro Starlight 帮助中心：项目分组对应 GitHub 分类目录，作者可以同步单篇文稿或整个项目，GitHub 提交再触发 Cloudflare Pages 部署。既有 GitHub 博客目标可以跨项目使用，不能直接表达“一个项目对应一个文档站”的组织关系。

## 决策

- GitHub 身份和 token 继续由应用级 publishing secret store 持有；项目只保存非敏感 `helpCenter` 仓库绑定与分组映射。
- 本地 Markdown 始终是内容事实源，GitHub 和 Starlight 是发布投影。
- 默认“待整理”不参与同步；其他分组自动获得唯一目录映射，并允许作者手动覆盖。
- 单篇与整项目共享同一转换、图片处理、远端清单和 Git Database API 原子提交引擎。
- `src/data/loby-docs.json` 是版本化导航与所有权清单。同步器只更新清单声明的文稿和图片，保留站点首页、代码、样式与未知文件。
- 文稿公开 slug 首次同步后固定；改变标题或分组只迁移仓库路径，不改变公开 URL。
- 整项目同步默认保留远端缺失文稿；只有作者显式开启清理时才删除已经不在同步范围的受管文件。
- 所有提交基于预期 branch HEAD，非 force 更新 ref；远端并发变化必须停止并重试。

## 结果

项目可以完整重建帮助中心绑定，新增分组无需预先规划 GitHub 文件夹；凭证不进入写作库。网站主题和内容发布保持解耦，单篇更新不会覆盖其他页面，批量同步也不会把模型缺失误判为删除。
