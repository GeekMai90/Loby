# Markdown 与 Obsidian 导入

## 产品入口

“文件 → 导入…”、项目右键“导入 Markdown…”与写作库空状态共用同一导入流程。全局入口默认写入收件箱，也允许在预览阶段切换到普通项目；项目右键入口直接选中目标项目。用户选择来源后必须先完成只读扫描与预览，确认前不得写入写作库或修改来源文件。

## 来源扫描

native `resources::markdown_import` 递归发现 `.md`、`.markdown`、`.txt` 与 `.text`，跳过隐藏目录和符号链接；扫描、YAML 解析、附件索引与图片复制运行在 blocking task，不占用桌面事件循环。一次扫描最多接收 5,000 篇、单篇最多 20 MB。格式损坏的 Front Matter 作为可见正文保留并返回警告，不能以空元数据覆盖原文。

普通 Markdown 图片先相对当前文稿解析。若来源路径的任一祖先包含 `.obsidian/`，系统将其识别为 Obsidian Vault，并读取 `.obsidian/app.json` 的 `attachmentFolderPath`；只有缺失或歧义仍存在时，界面才要求用户补充附件目录。扫描只在文稿目录、Vault 根目录、配置附件目录和用户明确选择的附件目录内解析，不搜索整个磁盘。

## 目录映射

- 收件箱保持扁平：递归发现全部文稿，但不为来源子目录创建分组。
- 普通项目的来源根目录文稿进入“待整理”；一级子目录创建同名分组。
- 多级目录展平为 `一级 / 二级`，不为导入单独增加嵌套项目模型。
- 已有同名分组直接复用；同内容文稿跳过，同标题不同内容增加数字后缀，禁止覆盖现有文稿。

## 元信息映射

外部导入只保留 Loby 系统字段和目标项目中已经存在、类型兼容的自定义属性。`title`、`tags`、`targetWords`、`description`（兼容读取常见别名 `summary`）、`created`/`createdAt` 与 `updated`/`modified`/`updatedAt` 进入标准文稿字段；外部 `status` 与 boolean `draft` 不映射为文稿状态，并在预览中列为丢弃项。Loby 自身不新增 `date` 系统字段，`date`、`publishDate`、`publishedAt` 只在目标项目已有日期类型“发布日期”属性时写入该自定义属性。

外部 `id`、`loby`、`hero_*`、`source` 与其他不匹配字段默认丢弃，并在预览中列出。每篇导入文稿始终生成新的 `sheet-` 加 26 位 Base32 身份，不能复用其他应用或另一个写作库的 ID。显式元信息时间优先，其次使用来源文件创建/修改时间，最后才使用导入时间。

## 图片提交

只复制已解析且实际被导入文稿引用的本地图片。图片进入写作库级 `assets/images/`，相同内容复用、同名不同内容追加短 hash；成功解析的 Obsidian embed 统一改写为相对文稿位置的标准 Markdown 图片引用，外部 URL 保持不变。缺失和歧义引用不得猜测或删除，用户选择继续时保留原始引用。

提交前重新扫描来源，避免预览后的文件变化被静默忽略；图片复制使用幂等内容寻址，随后通过写作库的立即保存协调器一次保存项目模型。保存失败不得更新 renderer 状态；已经复制但尚未被文稿引用的图片仍受“清理未使用图片”能力管理。

## 验证边界

- Rust 测试覆盖 Vault 配置识别、递归目录、相对图片、歧义附件、损坏 Front Matter 与图片内容去重。
- 前端模型测试覆盖字段白名单、文件时间回退、目标属性匹配、目录分组、收件箱扁平、重复文稿和图片引用改写。
- Dialog 测试覆盖自动识别摘要、字段去留预览和缺失附件补充入口。
- React 协调测试保护确认时重新扫描、图片传输、显式保存与 renderer 状态提交的先后顺序。
